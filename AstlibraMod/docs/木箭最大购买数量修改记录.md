# ASTLIBRA 木箭最大购买数量修改记录

## 目标

只把商店中“木箭”的最大购买数量从 `99` 扩展到 `999`，其他商品仍保持原来的 `99` 上限。同时调整数量选择框中的左右箭头和三位数字，使它们完整显示。

本文记录的是 x64dbg 运行时验证流程。正式 Mod 尚未写入项目代码，必须先由用户确认运行时效果。

## 当前已验证结论

- 游戏主模块：`astlibra.exe`
- 本次调试基址：`0x7FF7BAFE0000`
- 木箭物品 ID：`0xFA`
- 当前商品 ID 偏移：`astlibra.exe + 0x1D1992C`
- 购买数量计算点：`astlibra.exe + 0x405D27`
- 数量选择界面函数：`astlibra.exe + 0x441A40`
- 木箭数量计算已验证正确：最大可购买数为 `999 - 当前持有数`
- 其他商品走原始逻辑，最大值仍为 `99 - 当前持有数`

注意：绝对地址会受 ASLR 影响。正式代码必须使用“模块基址 + 偏移”，不能写死本次运行的 `0x7FF7...` 地址。

## 原始购买数量逻辑

关键位置：

```text
astlibra.exe + 0x405D27
本次绝对地址：0x7FF7BB3E5D27
```

原始指令：

```asm
mov r8d, edi
lea edx, [rbp+0x6E]
```

进入这里时，`EDI` 是商品原始最大购买数量。普通商品和木箭原始值都是 `99`。

不能直接修改较早出现的两个 `mov edi, 0x63`：

```text
astlibra.exe + 0x405613
astlibra.exe + 0x405AF9
```

修改这两处会导致购买界面消失，因此它们不是安全的最终修改点。

这里的 `0x3E7` 就是十进制 `999`。

## x64dbg 运行时验证方案

### 1. 暂停游戏

写入代码前先调用 `debug_pause`，避免游戏线程执行到只写了一半的补丁。

### 2. 分配代码内存

x64dbg MCP 的 `memory_allocate` 会分配一页内存，但默认权限是：

```text
PAGE_READWRITE
```

这块内存不能直接执行。此前直接跳入该内存，游戏在第一条指令处触发执行权限异常并暂停。

必须先使用 `VirtualProtectEx` 把页面权限改为：

```text
PAGE_EXECUTE_READWRITE
```

正式 DLL 中应直接使用：

```cpp
VirtualAlloc(
    nullptr,
    codeSize,
    MEM_COMMIT | MEM_RESERVE,
    PAGE_EXECUTE_READWRITE);
```

### 3. 写入条件代码

本次临时分配地址是：

```text
0x0000021B84DC0000
```

该地址只对本次进程有效，游戏重启后不能复用。

本次写入的机器码：

```text
50

81 38 FA 00 00 00
58

41 B8 E7 03 00 00
EB 03

```

其中两个绝对地址都必须在每次启动后重新计算：

- 当前商品 ID 地址：`moduleBase + 0x1D1992C`
- 返回地址：`moduleBase + 0x405D2D`

### 4. 使用模块内代码洞作为远跳转中继

购买数量入口只有 6 字节可覆盖，而临时分配内存通常距离主模块超过相对跳转的正负 2 GB 范围。因此先跳到模块内部代码洞，再通过绝对跳转进入远端代码。

模块内代码洞：

```text
astlibra.exe + 0x40DB10
本次绝对地址：0x7FF7BB3EDB10
```

16 字节中继代码：

```asm
push rax
mov rax, allocatedCodeAddress
xchg qword ptr [rsp], rax
ret
```

这种写法会跳到远端地址，同时保持原来的 `RAX` 和 `RSP`。

入口补丁：

```text
astlibra.exe + 0x405D27
```

```asm
jmp astlibra.exe+0x40DB10
nop
```

本次入口机器码：

```text
E9 E4 7D 00 00 90
```

### 5. 回读后再运行

至少回读并检查：

- 入口 6 字节
- 模块内 16 字节中继
- 远端条件代码
- 远端内存权限是否为 `PAGE_EXECUTE_READWRITE`

确认无误后调用 `debug_run`。

## 已踩过的坑

1. 把所有商品都改成 `999`

   原因是直接把通用逻辑中的 `mov r8d, edi` 改成了 `mov r8d, 999`。解决方法是先读取当前商品 ID，只对 `0xFA` 使用 `999`。

2. 购买界面消失

   原因是修改了 `astlibra.exe+0x405613` 或 `astlibra.exe+0x405AF9` 的 `mov edi, 0x63`。这两处必须保持原样。

3. 游戏页面卡住

   原因是跳入 `PAGE_READWRITE` 内存执行代码，触发执行权限异常。必须先改成可执行权限。

4. 误把右箭头当成左箭头

   `astlibra.exe+0x441BB0` 控制的是右箭头；真正的左箭头坐标在 `astlibra.exe+0x441A61`。

5. 汇编指令长度变长并覆盖后续指令

   `add ecx, 0x69` 原始长度为 3 字节。把立即数改成 `0x87` 时，汇编器生成了 6 字节指令并覆盖下一条指令。修改后必须检查指令长度和后续反汇编，不能只看汇编是否成功。

## 正式 DLL 实现要求

用户确认 x64dbg 最终效果后，再修改 `AstlibraMod` 项目。正式实现至少需要：

1. 使用 `GetModuleHandleW(nullptr)` 获取游戏模块基址。
2. 校验关键位置的原始字节，防止游戏版本变化后误写。
3. 使用 `VirtualAlloc` 分配 `PAGE_EXECUTE_READWRITE` 代码内存。
4. 根据实际地址生成条件代码和绝对跳转。
5. 使用 `VirtualProtect` 临时开放主模块代码页写权限。
6. 写入入口、中继和界面坐标补丁。
7. 调用 `FlushInstructionCache`。
8. 任一步失败时恢复已修改的原始字节并记录日志。
9. 不在 `DllMain` 中执行复杂初始化；由 `InitializeMod` 明确启动补丁。

## 箭头位置实测修正（2026-10-07）

本节 supersedes 前文对 `+0x441A61`、`+0x441B72`、`+0x441BB0` 的静态标注；前文保留作为历史探索记录。

最终实测修正：`+0x441A61` 控制中间数量框，`+0x441B72` 控制左箭头，`+0x441BB0` 控制右箭头。

之前按汇编出现顺序标注箭头位置的结论不准确。通过 x64dbg/x64mcp 逐个修改坐标立即数并观察画面后，当前确认如下：

```text
astlibra.exe + 0x441A61
add ecx, 0x69
```

修改该立即数后，中间数量框移动，因此它控制中间数量框的横坐标。

```text
astlibra.exe + 0x441B72
add ecx, 0x37
```

将 `0x37` 调小后，左箭头向数量框内部移动，因此确认该位置控制左箭头的横坐标。它不是通过代码出现顺序推断出来的，而是通过单变量运行时验证确认的。

```text
astlibra.exe + 0x441BB0
lea ecx, [rsi+0x9B]
```

将 `0x9B` 调小后，右箭头向数量框内部移动，因此确认该位置控制右箭头的横坐标。

通用验证方法：每次只修改一个坐标立即数，记录哪个画面对象移动；恢复原值后再测试下一个位置。多个 `call` 的先后顺序不代表屏幕上的左右顺序，最终对象名称必须以运行时画面验证为准。
